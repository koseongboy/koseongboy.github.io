01 · FACTORY ENGINE ROOM

7종 260개+자동 파싱하는 기획 CSV 데이터
O(1)인메모리 룩업 테이블 조회

기획 데이터 자동 파싱 및 O(1) 인메모리 캐싱 파이프라인

  • 기획자가 작성한 7종 260개 이상의 외부 CSV 데이터를 게임 실행 시 1회 파싱해 In-Memory Dictionary 및 Scriptable Object 형태의 룩업 테이블로 전환했습니다.
  • 기획 데이터가 수천 개 이상 늘어나도 코드 수정 없이 테이블 추가만으로 동작하는 확장성을 확보했습니다.

OS 레벨 백그라운드 키 입력 감지

  • Windows API의 Keyboard HookCallback을 활용해, 게임 클라이언트가 포커스를 잃은 상태에서도 OS 레벨 키보드 입력을 감지해 인게임 동력 자원으로 변환하는 시스템을 개발했습니다.

GitHub 잔디 스타일 출석 달력

  • 하루의 접속 시간과 키 입력량을 달력에 기록하고, GitHub 잔디 심기처럼 활동량에 따라 날짜 칸의 초록색 농도를 다르게 표시해 플레이 기록을 한눈에 볼 수 있게 했습니다.

게임 루프 기획

  • 키보드 입력 횟수가 공장의 동력을 가속시키는 메커니즘을 기획했습니다.
  • 동력 장치와 생산 장치를 분리하는 시스템을 기획했습니다.

03 · BOSS FIGHT: GLOBAL HOOK

OS 레벨 전역 후킹의 보안 취약점 진단과 구조적 타협

ISSUE
백그라운드 입력 감지를 위해 SetWindowsHookEx 전역 후킹을 구현했으나, 수집된 키 코드가 메모리에 적재되면 클라이언트 변조로 키로거로 악용될 수 있고, 백신 프로그램에 악성 코드로 오탐지될 위험도 컸습니다.
DECISION
근본 해결책인 MS 권장 규격 Raw Input API로의 전면 교체를 계획했지만, 기한 내 아키텍처 재구축은 리스크가 크다고 판단했습니다. 대신 어떤 키가 눌렸는지 식별하는 로직을 완전히 삭제하고, 이벤트 발생 시 의미 없는 더미 데이터만 큐잉하도록 마스킹했습니다.
RESULT
기한 내에 정보 유출 리스크를 원천 차단했습니다. 근본적인 API 교체는 기술 부채로 남았고, 향후 Raw Input API(RIDEV_INPUTSINK)로 마이그레이션해 백신 오탐지까지 해결하는 것이 다음 목표입니다.
