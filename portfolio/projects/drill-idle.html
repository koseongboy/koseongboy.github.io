01 · CORE SYSTEMS

7종 260개+자동 파싱하는 기획 CSV 데이터

기획 데이터 자동 파싱 및 인메모리 캐싱 파이프라인

  • 기획자가 작성한 7종 260개 이상의 외부 CSV 데이터를 게임 실행 시 1회 파싱해 Dictionary와 ScriptableObject 형태의 룩업 테이블로 변환했습니다.
  • 같은 형식의 데이터는 코드 수정 없이 CSV 행 추가만으로 게임에 반영됩니다.

OS 레벨 백그라운드 키 입력 감지

  • Windows API의 저수준 키보드 훅(SetWindowsHookEx(WH_KEYBOARD_LL), LowLevelKeyboardProc)으로, 게임 창이 포커스를 잃은 상태에서도 키 입력을 감지해 인게임 동력 자원으로 변환하는 시스템을 개발했습니다.

GitHub 잔디 스타일 출석 달력

  • 하루의 접속 시간과 키 입력량을 달력에 기록하고, GitHub 잔디 심기처럼 활동량에 따라 날짜 칸의 초록색 농도를 다르게 표시해 플레이 기록을 한눈에 볼 수 있게 했습니다.

게임 루프 기획

  • 키보드 입력 횟수가 공장의 동력을 가속시키는 메커니즘을 기획했습니다.
  • 동력 장치와 생산 장치를 분리하는 시스템을 기획했습니다.

02 · OUTCOMES

데이터 구조화 및 자동화 역량

  • 기획자가 관리하는 CSV 테이블을 게임 객체로 변환하는 파이프라인을 만들어, 기획 데이터 변경이 코드 수정 없이 반영되는 흐름을 구축했습니다.
  • 문서화된 기획 가이드라인을 클라이언트 시스템으로 옮기는 작업을 맡았습니다.

03 · TROUBLESHOOTING

OS 레벨 전역 후킹의 보안 취약점 진단과 구조적 타협

ISSUE
백그라운드 입력 감지를 위해 SetWindowsHookEx 전역 후킹을 구현했으나, 수집된 키 코드가 메모리에 적재되면 클라이언트 변조로 키로거로 악용될 수 있고, 백신 프로그램에 악성 코드로 오탐지될 위험도 컸습니다.
DECISION
Raw Input API로의 전환도 검토했지만, 기한 내 입력 구조 재구축은 리스크가 크다고 판단했습니다. 대신 어떤 키가 눌렸는지 식별하는 로직을 완전히 삭제하고, 이벤트 발생 시 의미 없는 더미 데이터만 큐잉하도록 마스킹했습니다.
RESULT
막은 것 — 키 식별 로직을 삭제해, 어떤 키가 눌렸는지가 게임 메모리에 남지 않습니다. 못 막은 것 — 저수준 전역 훅 자체는 계속 동작하므로 백신 오탐지 위험은 그대로 남아 있습니다.
LEARNED
Raw Input(RIDEV_INPUTSINK)도 백그라운드 키 입력을 받는다는 점은 같아서, API 교체만으로는 이 문제가 해결되지 않는다는 것을 확인했습니다. 수집하는 정보를 최소화하는 것이 핵심이라는 점을 배웠습니다.
